# FitDaero MVP 데이터 적재 명세

## 1. 원본 파일과 API 키 관리

- 원본 CSV와 컬럼 정의서는 Git에 올리지 않는다.
- 개발 환경에서는 프로젝트 외부 또는 Git 제외된 `data/inbound` 경로에 보관한다.
- 운영 환경에서는 컨테이너 외부 볼륨의 버전별 경로에 보관한다. 프로그램 원본은 운영자가 공식 포털에서 수동으로 내려받아 이 볼륨에 제공한다.
- 파일은 고정 이름으로 덮어쓰지 않고 `source/year-month/original-file-name` 형태로 보관한다.
- `APP_IMPORT_ON_STARTUP=false`가 기본값이다. 이때는 파일 적재와 외부 API 호출 없이 기존 DB 데이터로 추천 API만 제공한다.
- `APP_IMPORT_ON_STARTUP=true`일 때만 앱 시작 단계에서 볼륨의 프로그램 CSV와 체력 API 적재를 각각 시도한다. 한 원천의 실패는 다른 원천 적재를 막지 않는다. CSV 경로나 API 키가 제공되지 않은 원천은 경고 후 건너뛰며 기존 완료 데이터는 변경하지 않는다.
- 프로그램 포털의 로그인 세션을 이용한 HTTP 다운로드, 자동 다운로드 스케줄러와 백그라운드 자동 재시도는 만들지 않는다.
- 국민체력100 측정결과 API 키는 로컬 환경변수 `apiKey`로만 제공한다. 키와 키가 포함된 URL은 Git, DB, 로그에 남기지 않는다.
- `data_import`는 원천 버전의 마지막 처리 상태를 보관한다. 개별 실행 시도를 별도 테이블에 누적하지 않는다.

## 2. 공통 적재 절차

```text
앱 시작 시 `APP_IMPORT_ON_STARTUP` 확인
    ├─ `false` → 적재 생략, 기존 완료 데이터 사용
    ↓ `true`
프로그램 파일 또는 API 요청 조건 검증
    ↓
data_import 생성 또는 FAILED 행 재시도 (RUNNING)
    ↓
소스별 변환·검증·원자적 upsert 또는 집계
    ↓
건수 기록 후 COMPLETED 또는 FAILED
```

파일 적재는 UTF-8·필수 헤더·파일 SHA-256을 검증한다. API 배치는 요청 조건을 정규화한 `request_signature`를 기록한다. 원천별 필수값은 애플리케이션 검증으로 확인하며, DB가 지원하면 동일 규칙을 `CHECK` 제약으로도 강제한다. 두 방식 모두 같은 식별자의 상태를 다음처럼 처리한다.

| 상태 | 실행 처리 |
| --- | --- |
| `COMPLETED` | 적재하지 않는다. |
| `RUNNING` | 중복 실행하지 않는다. |
| `FAILED` | 다음 `APP_IMPORT_ON_STARTUP=true` 실행에서 같은 `data_import` 행을 `RUNNING`으로 변경해 재시도한다. |

날짜·필수 행값처럼 개별 행의 형식 오류는 해당 행만 제외하고 `failure_count`에 기록한다. 파일 헤더·인코딩·파일 자체·DB·API 오류는 원천 수준 실패다. 원천 수준 실패는 해당 원천의 모든 변경을 롤백하고 `FAILED` 및 민감정보를 제외한 `last_error_message`를 기록한다. 유효 행이 하나도 없으면 원천 수준 실패로 처리한다. 적재 실패는 앱 시작을 막지 않으며, 추천은 이전 `COMPLETED` 데이터만 사용한다.

## 3. 공공체육시설 프로그램 적재

### 필수 컬럼

`FCLTY_NM`, `FCLTY_ADDR`, `CTPRVN_CD`, `CTPRVN_NM`, `SIGNGU_CD`, `SIGNGU_NM`, `PROGRM_TY_NM`, `PROGRM_NM`, `PROGRM_TRGET_NM`, `PROGRM_BEGIN_DE`, `PROGRM_END_DE`, `PROGRM_ESTBL_WKDAY_NM`, `PROGRM_ESTBL_TIZN_VALUE`, `PROGRM_PRC`, `PROGRM_PRC_TY_NM`

주소·대상·시간·가격·가격 유형은 헤더가 반드시 있어야 하지만, 값이 비어 있으면 각각 빈 문자열 또는 `null`로 정규화한다. 홈페이지·연락처·좌표·모집정원은 선택 컬럼이며, 없거나 비어 있으면 `null`로 둔다. `FCLTY_NM`, 시도·시군구 코드·명, `PROGRM_NM`, 시작일·종료일은 행값도 필수이며 비어 있으면 해당 행을 제외하고 `failure_count`를 증가시킨다. 프로그램 유형이 비어 있으면 프로그램명으로만 분류하고, 요일이 비어 있거나 해석되지 않으면 저장하되 추천 후보에서 제외한다.

### 변환 규칙

- 날짜: `PROGRM_BEGIN_DE`, `PROGRM_END_DE`의 `yyyyMMdd`를 날짜로 변환한다. 변환할 수 없으면 해당 프로그램 행을 제외하고 `failure_count`를 증가시킨다.
- 시설: 정규화한 `FCLTY_NM + FCLTY_ADDR`를 시설 키로 사용해 upsert한다. 원본에 안정적인 시설 식별자가 없으므로 주소 정정은 새 시설로 보일 수 있다.
- 프로그램: 시설 키, 정규화한 프로그램명, 시작일, 종료일, 요일 비트마스크, 정규화한 시간, 정규화한 대상을 결합한 SHA-256 키로 파일 내 중복을 제거한 뒤 upsert한다. 프로그램명·시간·대상은 앞뒤 공백 제거, 연속 공백 축소, HTML 줄바꿈을 공백으로 치환해 정규화한다.
- 요일: `월`~`일` 포함 여부를 월~일 비트로 변환한다. `매일`은 모든 요일로 변환한다. 하나도 해석하지 못하면 `weekday_mask`를 비운다.
- 시간: `PROGRM_ESTBL_TIZN_VALUE`는 원문만 저장한다. 시간대 표기가 불완전하므로 파싱·필터링하지 않는다.
- 가격: `PROGRM_PRC`와 `PROGRM_PRC_TY_NM`을 원문 의미대로 저장한다. 단위가 일관되지 않으므로 월 가격으로 환산하지 않는다.
- 대상: 정규화한 `PROGRM_TRGET_NM`을 다음 우선순위로 분류한다. `성인`, `실버`, `노인`, `경로`, `65세 이상`은 `ADULT_EXPLICIT`이다. `전체`, `누구나`, `일반`, 또는 `유아·어린이·청소년·중학생·중고생·숫자세` 뒤에 `이상`이 붙은 표현은 `ADULT_POSSIBLE`이다. 앞선 조건에 맞지 않는 `유아`, `어린이`, `초등`, `미취학`, `청소년`은 `CHILD_ONLY`이며 나머지·빈값은 `UNKNOWN`이다. 예를 들어 `성인/청소년`은 `ADULT_EXPLICIT`, `청소년이상`은 `ADULT_POSSIBLE`, `초등학생`은 `CHILD_ONLY`다.
- 종목: `PROGRM_TY_NM`에서 먼저, 매칭되지 않을 때 `PROGRM_NM`에서 [추천 명세](recommendation.md)의 키워드를 찾는다. 같은 텍스트에 여러 종목 키워드가 있으면 가장 왼쪽 키워드를 사용하며, 같은 위치면 명세 표의 순서로 고정한다. 분류하지 못하면 `OTHER`다.
- 가격, 가격 유형, 모집정원, 프로그램 유형, 종목군, 성인 대상 판정은 키에 포함하지 않고 같은 프로그램 키의 가변 값으로 갱신한다. 대상은 별도 과정 구분을 위해 키에 포함하므로 대상 정정은 새 프로그램으로 보일 수 있다.
- 원본 CSV에 없다는 사실만으로 기존 시설·프로그램을 비활성화하거나 삭제하지 않는다. 원본에는 과거 종료 프로그램도 포함되므로 추천 후보 조회에서 `ends_on >= 요청일`을 만족하는 행만 사용한다. 유효 행 upsert와 `COMPLETED` 전환은 하나의 트랜잭션으로 처리한다.

## 4. 국민체력100 측정결과 API 배치 적재

### 요청 조건

- HTTPS `https://apis.data.go.kr/B551014/SRVC_NFA_TEST_RESULT/TODZ_NFA_TEST_RESULT_NEW`를 사용한다.
- `serviceKey`에는 환경변수 `apiKey`, `resultType`에는 `json`을 사용한다. API 키와 키가 포함된 요청 URL은 기록하지 않는다.
- `age_gbn=성인`, `test_sex=F` 또는 `M`, `starttest_ym=202201`, `endtest_ym=실행 시점의 yyyyMM`으로 요청한다.
- 페이지 단위로 수집하며, 두 성별 요청 조건·수집 기간·엔드포인트를 정규화한 값으로 `request_signature`를 만든다.

### 집계 제한

- `age_degree`가 19~64세이고 `test_sex`가 `F` 또는 `M`인 행만 사용한다.
- `item_f028`, `item_f012`, `item_f019`만 집계하며 각 항목은 숫자로 변환 가능한 값만 사용한다.
- 연령은 `19~29`, `30~39`, `40~49`, `50~59`, `60~64`로 구간화한다.
- 개인별 측정행과 `pres_note`는 저장하거나 로그에 남기지 않는다.

### 생성 결과

성별·연령대·측정항목별로 다음만 `fitness_reference`에 생성한다.

- 유효 표본 수(100건 이상인 조합만 생성)
- 25·50·75 분위

API 응답의 개인별 측정행과 `pres_note`는 서비스 DB에 저장하거나 로그에 남기지 않는다.

정밀 추천은 `completed_at DESC, id DESC` 순서로 선택한 가장 최근 `COMPLETED` 상태 `FITNESS_MEASUREMENT_API` 적재의 `fitness_reference`만 조회한다.

## 5. 데이터 한계

2022년 이후 공개 API의 성인 표본은 MVP 비교 기준일 뿐 국민 전체를 대표하는 공식 인증 기준이 아니다. 따라서 정밀 분석은 `낮음 / 보통 / 높음`만 제공하며 정확한 백분위나 인증 등급으로 표현하지 않는다.

채택 검증 시 2022년 이후 성인 표본은 여성 246,266건, 남성 373,301건으로 조회됐다. 이 수치는 API의 실시간 갱신에 따라 달라질 수 있으며, 실제 적재 시점의 항목별·성별·연령대별 유효 표본 수를 최종 기준으로 사용한다.

## 6. 적재 검증 기준

- `APP_IMPORT_ON_STARTUP=false`에서는 파일 접근과 체력 API 호출이 발생하지 않는다.
- 같은 완료 파일·같은 완료 API 요청은 다시 적재하지 않는다.
- 프로그램 행 오류는 유효 행 적재를 막지 않지만, 원천 수준 실패는 해당 원천의 변경을 모두 롤백한다.
- 프로그램 CSV 실패 뒤에도 체력 API 적재는 독립적으로 시도하며, 반대 경우도 같다.
- 원본 개인 측정행, `pres_note`, API 키와 키가 포함된 URL은 DB·로그·Git에 남지 않는다.
